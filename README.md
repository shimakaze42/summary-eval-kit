# summary-eval-kit — 文書要約エージェント評価キット

章別要約が原文にどれだけ忠実かを、**LLM を使わず機械的に採点する**小さな評価キットです。

LLM に要約を作らせると、もっともらしいが原文にない数字や固有名詞が混ざることがあります。
かといって別の LLM に「この要約は正しいですか？」と聞く（LLM-as-judge）方式は、
採点自体に LLM 呼び出しが要り、スコアの再現性も揺れます。
本キットは発想を逆にして、**「要約中の数字・固有名詞が、対応する原文に実在するか」を
文字列照合で数える**ことで、決定的（何度回しても同じ結果）な物差しを提供します。

## 測る指標

| 指標 | 内容 |
|---|---|
| 数字チェック | 要約中の数値表現（単位つき）を抽出し、対応する章の原文に存在するか照合。なければハルシネーション候補 |
| 固有名詞チェック | 要約中のカタカナ語・短い鉤括弧用語を抽出し、原文に存在するか照合 |
| 章カバー率 | 全章のうち要約が付いている割合、章ごとの要約長／原文長 |

### 設計上の約束：「候補」と「確定」を分ける

原文に文字列として見つからないものは、すべて**ハルシネーション候補**として列挙します。
表記ゆれ・OCR 誤り・言い換えでも未一致になるため、「候補＝捏造」ではありません。
確定判定は、候補を原文と見比べて人が行う前提の設計です。
実際に運用してみると、候補2件のうち1件は言い換えによる誤検出、もう1件は
「機械が拾って人が見る価値があった」言い換え混入でした（詳細は
[results_v1_spotcheck.md](results_v1_spotcheck.md)）。

## 使い方

```bash
python3 eval_summary.py --data-dir /path/to/data
# 出力: results_v1.md（人用レポート）、results_v1.json（機械用）
```

標準ライブラリのみで動作します（Python 3.10+）。引数なしで実行すると
`~/workspace/kindle_summarizer/jinzai/` を既定のデータ置き場として読みます。

### 入力データの形式

| ファイル | 形式 |
|---|---|
| `book.txt` | 原文テキスト。ページ区切りは `[p.N]` マーカー（行頭） |
| `summary.md` | 章別要約。`## ` 見出しで節に分割し、見出しは `chapters.json` の章タイトルと対応づける |
| `chapters.json` | `{"chapters": [{"title": "...", "start": 開始ページ, "end": 終了ページ}, ...]}` |

原文・要約データは読み取りのみで、改変しません。

## 実測結果（同梱）

坪谷邦生『図解 人材マネジメント入門』（全318ページ、OCRテキスト）の章別要約に適用した結果です。

| 項目 | 結果 |
|---|---|
| 章カバー率 | 全14章中 11章（78.6%）。未カバーは前付け・推薦図書・参考文献など。本編 Chapter 1〜10 と「おわりに」は全章カバー |
| 数字精度 | 92件中 91件が原文に存在（98.9%）。候補1件 |
| 固有名詞精度 | 305件中 304件が原文に存在（99.7%）。候補1件 |

- 章ごとの全結果と第1章の詳細（数字・固有名詞を1件ずつ判定）: [results_v1.md](results_v1.md) / [results_v1.json](results_v1.json)
- 候補2件を原文と目視照合した記録: [results_v1_spotcheck.md](results_v1_spotcheck.md)

**読み方の注意**：この高い精度は、土台の要約自体が作成時に原文照合を経た品質だったためでもあります。
「悪い要約をどれだけ検出できるか（検出力）」の検証は、プロンプト違い・モデル違いの
要約バリエーションを当ててみる次段階の課題です（後述の限界も参照）。

## データについて（著作権）

評価対象の**書籍原文テキストと要約全文は、このリポジトリには含まれていません**。
同梱しているのはコード、手法説明、章ごとの指標テーブル、および抽出された数字・
固有名詞の短い断片レベルの判定結果のみです。再現には各自で用意した
原文・要約データを上記形式で置いてください。

## v1 の限界（既知）

- 原文が OCR テキストの場合、誤読が混ざる。原文側の誤読は、正しい要約語でも未一致にしうる。
- 漢数字、助数詞の言い換え（「3観点」→「3つ」）、丸めた数字は拾い切れない／照合できないことがある。
- 固有名詞の抽出はカタカナ語と短い鉤括弧用語のみ。漢字の人名・組織名は対象外。
- 「原文に存在する」≠「その文脈で正しく使われている」。意味の正しさの判定は v2 以降の領分。

## 先行事例との関係

- DeepEval / RAGAS の主流指標（Faithfulness、Hallucination、Summarization）は LLM-as-judge 型。
  本キットはあえて決定的指標に絞り、再現性を優先した。
- RAGAS の entity recall（固有名詞の重なり率）は、本キットの固有名詞チェックと発想が近い。
- 古典の ROUGE は全文の n-gram 一致を見るが、本キットは「数字と固有名詞」という
  事実要素に絞った厳密照合に寄せている。

## ファイル構成

- `eval_summary.py` — 本体
- `results_v1.md` — 実行結果レポート（第1章の詳細つき）
